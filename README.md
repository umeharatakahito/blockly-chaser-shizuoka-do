# blockly-chaser-shizuoka-do

Blockly CHaser サーバーの **Cloudflare Durable Objects 版**。

**デプロイ済み**: https://blockly-chaser-shizuoka-do.blockly-chaser-shizuoka-do.workers.dev

Node 版 [blockly-chaser-shizuoka](https://github.com/umeharatakahito/blockly-chaser-shizuoka)
を Cloudflare 側で動くように移植し、その上に静岡大会向けの機能を足したものです。
`wrangler dev` で会場LANでもそのまま動きます。

## なぜ作ったか

Node 版は「サーバーを常時動かしておく」前提です。会場LANでは理想的ですが、
事前練習のためにインターネットへ出そうとすると置き場所が要ります。
無料の選択肢を調べたところ、この用途にはどれも足りませんでした。

| 方法 | 問題 |
|---|---|
| Cloudflare Tunnel | Mac を起動し続ける必要がある |
| ngrok 無料 | 月20,000リクエスト。**1画面40リクエストなので月500表示で枯渇** |
| GCP 無料枠 | 下り月1GB。**1画面2.62MB なので月390表示で枯渇**。外部IPも有料 |

Durable Objects なら Cloudflare 側で動くため機材に依存せず、
無料枠もこの用途には余裕があります。

| 項目 | 無料枠 | この用途 |
|---|---|---|
| リクエスト | 10万/日 | 1画面40リクエスト → **1日2,500画面表示** |
| WebSocket 受信 | 20通で1リクエスト換算 | 試合中の通信はほぼ無視できる |
| SQLite | 書き込み10万行/日・保存は無課金 | 桁違いに余裕 |
| 静的ファイル | 実質無制限 | Blockly の 4.8MB もここ |

無料プランで作れるのは **SQLite バックエンドの Durable Objects のみ**です。
`wrangler.jsonc` の migration は `new_sqlite_classes` を使っています。

### サンプルプログラム

`public/samples/sample_basic.xml`。プログラミングのデータ選択で「サンプル」を選ぶと編集画面に開きます。
初級のブロックだけで組んであり、1ターンに1つだけ行動します。

1. となりに相手がいたらブロックを置いてアタック
2. ななめに相手がいたら動かずに様子を見る(近づくと先にアタックされるため)
3. となりのアイテムを取る
4. 最初にランダムに決めた向きへ進み続ける
5. ふさがれたら向きを決め直す

L5 のボットと互角程度で、改良の余地を残してあります。

### ボット対戦

`src/game/bot.js`。本家の CPU(3段階)とは別物で、レベルを上げると順に能力が解放されます。

| レベル | 解放されるもの |
|---|---|
| L1〜 | ふらふら歩く。ブロックへ突っ込むこともある |
| L3〜 | 隣の相手を叩き始める(L8 で必ず叩く) |
| L6〜 | 見たマスを覚える。相手の隣で手番を終えない |
| L8〜 | 袋小路を避ける |
| L10〜 | 迷わなくなる。相手の位置を常に察知 |
| L12〜 | 負けていると追いかける |
| L15〜 | 相手の逃げ道を塞ぐ |
| L20〜 | 盤面全体を知っている |
| L25〜 | 2手先まで読む |

ボット同士を戦わせた勝率で、上のレベルが下のレベルに勝ち越すことをテストで確かめています。
ボットに勝つと名前を残せます。名前は `src/names.js` で検査し、卑猥な語は表記ゆれ
(カタカナ・全角・記号の挟み込み・leet)を潰した上ではじきます。スキップすると
「すばやいカワウソ #0427」のような名前が自動で付きます。

### ゴースト対戦

ボット対戦で人間側が指した手をそのまま記録しておき、別の人がそれと戦えます。
ゴーストは記録した側(cool)に入り、挑戦者は hot になります。
記録が尽きたあとは、元の試合で戦ったボットと同じレベルで動き続けます。

### 運営モード

トップメニューでは普段隠してあり、**画面上部のバーを5回押す**と現れます(同じタブでは開いたまま)。
これは参加者に押させないための隠しで、鍵の代わりではありません。運営ページ自体は鍵で守られています。

鍵は Wrangler の secret に置きます。

```bash
npx wrangler secret put ADMIN_KEY
```

`/admin` で鍵を入れると Cookie(鍵から作った HMAC)で1週間通れます。
鍵が未設定のときは localhost からだけ運営モードが開きます(手元で試すため)。
公開環境では必ず設定してください。未設定だと `/admin` と `tool/smoke.mjs` が警告します。

### 対人対戦と観戦

プログラミング画面から `server_join` ブロックで対人ルーム(room_1xx)に入ると、
2人目が来るまで待ち、揃った時点で始まります。同じ合言葉の人だけが同じ試合に入ります。
`/vs` の対戦画面は、1台のPCで両方の .blch を読み込んで戦わせる形です。
片側を「開放」すると、その枠に別のPCのプログラミング画面から入れます。

## 構成

```
Workers Assets   静的ファイル(Blockly・CSS・画像・書き出した画面)
Worker           ルーティング。状態は持たない
MatchRoom (DO)   対戦ルーム1つにつき1インスタンス。盤面・スコア・WebSocket・ボット
TournamentStore  対戦表と試合結果。大会に1つ
MovieStore       動画の目録。動画そのものは預からない
RecordStore      ボット対戦の記録(ゴースト)・エントリー・提出された .blch
```

Node 版が `server_store[room_id]` に持っていた状態が、そのまま
「ルームIDで選ばれる Durable Object」に対応します。
使っていないルームは WebSocket hibernation で眠り、接続を保ったまま課金対象から外れます。

### 移植で難しかったところ

**タイマー** — Durable Objects のアラームは1オブジェクトに1つだけです。
Node 版は `setTimeout` を14箇所で使っているため、そのままでは移せません。
`src/timers.js` が予定を SQLite に並べ、最も早いものだけをアラームに設定し、
鳴ったら残りを設定し直します。

**Socket.IO** — サーバーは Workers で動きません。
ただしクライアントは `socket.emit` / `socket.on` を49箇所で使っており、
書き換えると練習環境との差が大きくなります。
`public/javascripts/socket-shim.js` が同じ形の窓口を生の WebSocket の上に用意し、
Durable Object 側も本家と同じイベント名で話すようにしてあります。

**EJS** — Workers ではサーバーサイド描画ができないため、
`tool/build_views.mjs` がビルド時に言語ごとの静的 HTML へ変換します(102ページ)。
対戦表や動画一覧など動的な部分は、ブラウザ側で組み立てます。

**セル値** — `1` がブロック、`2` がアイテムで直感と逆です。
Node 版で実際に受け取った9マスの値をテストに埋め込み、移植したエンジンが
同じ値を返すことを確認しています。

## 動かす

```bash
npm install
npm run dev        # 画面を書き出してから wrangler dev
```

別のターミナルで:

```bash
npm test                          # 単体テスト(エンジン・ボット・名前の検査など)
node tool/smoke.mjs               # ボット対戦・ゴースト・対人・観戦・運営の鍵を通しで確認
node tool/play.mjs                # CPU と1試合戦う
node tool/play.mjs http://localhost:8787 'room_110?abc'   # 対人ルーム(2つ起動すると始まる)
```

`tool/smoke.mjs` と `tool/play.mjs` は URL を渡せば公開環境でも使えます。

## デプロイ

```bash
npm run deploy
```

## 試合動画

動画そのものはこのサーバーに置きません。YouTube などに上げてもらい、
`/movies/admin` で **URL だけを登録**します。

当初は Cloudflare の R2 に置く形で作りましたが、R2 の有効化には
支払い方法の登録が要るため、この方式に変えました。追加費用も容量制限もありません。

対応しているのは次の4つです。

| 置き場所 | 備考 |
|---|---|
| YouTube | 限定公開でも可。追跡の少ない nocookie ドメインで埋め込む |
| Google ドライブ | 共有を「リンクを知っている全員」にしておく |
| Vimeo | |
| mp4 / webm への直リンク | |

埋め込み先はこの4つに限っています。任意のURLを iframe に入れられると、
運営以外が登録できるようになったときに何でも埋め込める穴になるためです。
`javascript:` や `data:` も弾きます。

非公開にしても記録は消しません。誤操作から戻せるようにするためです。

## 残っていること

- 通常モードの画面はどれも PC 向けの幅で作ってあり、スマートフォンでは崩れる
- ボット対戦の記録は 500 件を超えると名前のない古いものから消える
- 対戦画面(`/match`)は1台のPCで両方の .blch を読み込む前提。別々のPCから戦う場合は
  プログラミング画面から同じ合言葉で対人ルームに入る

## 本家との違い

Socket.IO を生の WebSocket に変えたため、通信の実装は練習環境と別物です。
`.blch`・`.xml`・`.json` の読み込みと、それを使った試合はこの環境で確認済みですが、
参加者の実物のファイルで一度は試してください。
